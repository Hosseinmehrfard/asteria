# Asteria — وب‌سایت دو‌زبانه آسترولوژی و پنل مدیریت

یک پروژه مستقل و قابل توسعه با **React + Vite** در سمت کاربر و **Node.js + Express + SQLite** در سمت سرور؛ با طراحی متفاوت از سایت مرجع. رابط فارسی (راست‌به‌چپ) و انگلیسی (چپ‌به‌راست) و داده‌های محتوایی هر دو زبان پشتیبانی می‌شوند.

> **وضعیت:** سورس یک نسخه کاربردی اولیه (MVP) است؛ نه کپی کامل/تأییدشده تمام قابلیت‌های سایت مرجع و نه محصول آماده بهره‌برداری مالی بدون پیکربندی. در این محیط، به علت نداشتن دسترسی به رجیستری npm، نصب وابستگی‌ها و تست یکپارچه در مرورگر انجام نشد. تست‌های نحو و راه‌اندازی اولیه SQLite و پشتیبان‌گیری اجرا شده‌اند.

## استقرار از GitHub روی VPS (Ubuntu 24.04)

**نسخه آماده GitHub:** فایل‌ها را از ZIP استخراج کنید و *محتوای پوشه پروژه* را به یک repository جدید GitHub منتقل کنید. فایل `.env`، پایگاه داده، فایل‌های آپلود شده و پوشه `storage/` نباید وارد Git شوند.

در VPS بعد از تنظیم DNS دامنه:

```bash
# پس از ساخت مخزن GitHub و فراهم کردن دسترسی در VPS:
sudo mkdir -p /opt/asteria
sudo chown "$USER":"$(id -gn)" /opt/asteria
git clone https://github.com/YOUR_USERNAME/asteria-platform.git /opt/asteria
cd /opt/asteria
bash scripts/install-vps.sh astro.example.com
```

برای **به‌روزرسانی بعدی بدون حذف اطلاعات**:

```bash
cd /opt/asteria
bash scripts/update-vps.sh
```

برای **بکاپ گرفتن از دیتابیس و آپلودها**:

```bash
bash scripts/backup-vps.sh
```

اسکریپت نصب Ubuntu 24.04 می‌تواند Docker و Compose را نصب کند و Caddy را برای HTTPS خودکار راه‌اندازی می‌کند. یک دامنه با رکورد DNS صحیح، پورت‌های عمومی 80 و 443 و دسترسی به GitHub/رجیستری ایمیج‌ها لازم است. مخزن خصوصی به احراز هویت مناسب روی VPS نیاز دارد. **راهنمای کامل مرحله‌به‌مرحله:** [`docs/GITHUB_VPS_FA.md`](docs/GITHUB_VPS_FA.md).

## پیش‌نیاز

## نصب و اجرای محلی

```bash
# پس از خارج کردن فایل ZIP وارد پوشه پروژه شوید
cd asteria-bilingual-platform

# در لینوکس/macOS: cp .env.example .env
# در Windows PowerShell: Copy-Item .env.example .env
npm install
npm run setup-admin
npm run dev
```

آدرس وب‌سایت: `http://localhost:5173`

آدرس ورود: `http://localhost:5173/login`

آدرس پنل: `http://localhost:5173/admin`

API به طور پیش‌فرض روی `http://localhost:4000` اجرا می‌شود. اگر برای نخستین بار مدیر می‌سازید، ایمیل، نام و **رمز عبور حداقل ۱۲ کاراکتری** انتخاب کنید. ورودی رمز در اسکریپت ساخت مدیر هنگام تایپ **قابل مشاهده است**؛ دستور را در محیط خصوصی اجرا کنید. هیچ نام کاربری یا رمز عبور پیش‌فرضی وجود ندارد.

### اجرای انتشار محلی

```bash
npm run build
npm start
```

بعد از build، فرانت‌اند نیز توسط سرور در `http://localhost:4000` سرو می‌شود. در محیط واقعی، `.env` را به‌صورت زیر تنظیم کنید و از HTTPS پشت reverse proxy استفاده کنید:

```env
NODE_ENV=production
PORT=4000
APP_ORIGIN=https://example.com
DB_PATH=./server/data/asteria.sqlite
MAX_UPLOAD_MB=20
# TRUST_PROXY=1  # فقط اگر پشت پراکسی قابل‌اعتماد اجرا می‌کنید
```

**توجه:** کوکی ورود در محیط production دارای پرچم Secure است؛ بنابراین باید سایت را با HTTPS باز کنید.

## پنل مدیریت کامل در محدوده نسخه اولیه

پنل `/admin` شامل **۲۲ بخش** است: نمای کلی و درآمد تأییدشده، مقاله‌ها، محصولات، دوره‌ها، درس‌های دوره‌ها، دسته‌بندی‌ها، خدمات، صفحات، پرسش‌های متداول، دیدگاه‌ها، بنرها، سفارش‌ها، رزروها، پیام‌ها، کاربران/نقش‌ها، کدهای تخفیف، کتابخانه فایل‌ها، مشترکان خبرنامه، فهرست چارت‌های ذخیره‌شده، تنظیمات سایت، سوابق اقدامات، خروجی JSON.

برای تمام انواع محتوا می‌توان عنوان، متن و خلاصه جداگانه فارسی/انگلیسی، تصویر، وضعیت انتشار، URL کوتاه، اولویت نمایش و اطلاعات تکمیلی تعیین کرد.

- `admin`: تنظیمات، نقش‌ها، تغییر سفارش‌ها، گزارش اقدامات و سایر قابلیت‌ها.
- `editor`: مدیریت محتوای دو‌زبانه، محصول، دوره، درس، دسته‌بندی، بنر، فایل و تخفیف.
- `support`: مشاهده سفارش‌ها، تأیید وضعیت سفارش‌ها، پاسخ‌گویی به درخواست‌ها و رزروها.
- `customer`: حساب شخصی و خرید.

### فرآیند فروش و دسترسی به فایل

1. مشتری سفارش ثبت می‌کند؛ وضعیت اولیه `awaiting_payment` است.
2. **هیچ پولی جابه‌جا نمی‌شود** و پرداخت آنلاین انجام نمی‌شود.
3. مدیر یا پشتیبان تنها پس از **تأیید واقعی دریافت وجه در بیرون از برنامه** می‌تواند وضعیت را `paid` کند.
4. دسترسی درس‌های غیررایگان و فایل دانلودی خصوصی تنها برای حساب ثبت‌کننده سفارشِ تأییدشده فعال می‌شود.
5. موجودی محصولات هنگام تغییر به وضعیت پرداخت‌شده کاهش می‌یابد و در بازپرداخت بازمی‌گردد.

برای فایل دیجیتال: در پنل «کتابخانه رسانه»، فایل PDF/ZIP/EPUB/MP3/MP4 را با گزینه «فایل خصوصی» آپلود کنید، سپس **شناسه فایل** را در قسمت Extra metadata محصول قرار دهید:

```json
{"type":"digital","fileId":"ID_FROM_PRIVATE_UPLOAD"}
```

برای کالای فیزیکی:

```json
{"type":"physical"}
```

برای دوره، درس‌ها را از قسمت «درس‌های دوره‌ها» اضافه کنید. مشخصه `preview` دسترسی رایگان به هر درس را کنترل می‌کند.

## داده‌های اولیه و رسانه‌ها

پروژه در اولین اجرا مجموعه‌ای از داده‌های نمایشی اصیل (مقاله‌ها، محصول‌ها، دوره‌ها، خدمات، بنرها، پرسش‌ها) به هر دو زبان ایجاد می‌کند. **تصاویر و محتوای دارای حق نشر از سایت مرجع کپی نشده‌اند**. قیمت‌ها، موجودی، توضیحات، فایل‌های فروش و اطلاعات تماس پیش از انتشار باید جایگزین شوند.

تصاویر عمومی در `server/uploads/public/` و فایل‌های دانلودی خصوصی در `server/uploads/private/` ذخیره می‌شوند. SQLite پیش‌فرض در `server/data/asteria.sqlite` است؛ این فایل‌ها در ZIP توزیع وجود ندارند و هنگام استفاده ایجاد می‌شوند.

## پشتیبان‌گیری

```bash
npm run backup
```

نسخه پشتیبان سازگار با SQLite در `backups/` ایجاد می‌شود؛ فایل‌های بارگذاری‌شده را **جداگانه** کپی کنید. خروجی JSON پنل برای گزارش و جابه‌جایی داده است و جایگزین پشتیبان SQLite نیست.

## Docker

```bash
# Linux / macOS: APP_ORIGIN=https://example.com docker compose up -d --build
# Windows PowerShell: $env:APP_ORIGIN='https://example.com'; docker compose up -d --build

docker compose exec web node server/setup-admin.js
```

پورت 4000 به `127.0.0.1` سیستم میزبان محدود است. Nginx یا Caddy با HTTPS باید درخواست‌های بیرونی را به آن منتقل کند. مسیر `storage/` پایدار و قابل پشتیبان‌گیری است. مستند راه‌اندازی در `docs/DEPLOYMENT_FA.md` موجود است.

## تست و مرزهای قابلیت

```bash
npm run check
npm run test
```

`npm run test` تست‌های پایگاه داده و کنترل حداقل امکانات هسته را اجرا می‌کند. تست واقعی UI، تراکنش‌های پرداخت، استرس، ارزیابی امنیت و بارگذاری در سرور واقعی همچنان موردنیاز است.

**این نسخه فاقد موارد زیر است:** درگاه پرداخت واقعی، تأییدیه/تراکنش درگاه، ارسال ایمیل و بازیابی رمز از طریق ایمیل، رزرو دارای کنترل تداخل زمانی، بسته کامل SEO/SSR، ویدئوها و فایل‌های دارای مجوز واقعی، ترجمه ماشینی خودکار، مقالات و محصولات کامل سایت مرجع، تفسیر اختصاصی حرفه‌ای چارت و محاسبه خانه‌های Placidus. داده‌های نجومی و تفسیر نمادین از هم تفکیک شده‌اند. اطلاعات زمان منطقه‌ای تاریخی و تغییر ساعت تابستانی باید توسط کاربر با دقت وارد شود.
